Gandalf checks before runtime.

The gate has four jobs: scan the surface, decide from local evidence, enforce before execution, then keep history for review.

Scan

Read the whole tool surface

Skill files, bundled scripts, MCP configs, launch commands, endpoint metadata, env names, and header names are scanned together.

Decide

Use cache state and local rules

Gandalf compares changed files, corrupted cache entries, local findings, and optional engine results before a tool runs.

Enforce

Block unsafe calls in the hook

The PreToolUse hook stops high-risk skills and MCP tools before command execution begins.

Remember

Keep local history

Scan results, runtime allows, runtime blocks, acknowledgements, and false-positive marks stay available for review.

Questions security teams ask first.

Does Gandalf replace reading code?
No. Gandalf blocks known risk and unscanned runtime. You still own trust decisions.
Can Claude still inspect a skill?
Yes. Reading is allowed. Running is gated.
What gets blocked?
Unscanned skills, changed skills, corrupted cache entries, and critical or high findings. MCP tools are blocked under enforcement.
Are secrets sent anywhere?
No with the local engine. Secret values are redacted and never written to cache or history.
Can findings be reviewed?
Yes. Run gandalf --review to inspect, acknowledge, or mark reviewed false positives.

Checked code runs. Unsafe code stops.

One local scan creates the verdict. The hook enforces it every time an agent tries to run a tool.
