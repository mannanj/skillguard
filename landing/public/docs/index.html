Docs

Gandalf scans agent skills and MCP servers before they run. Use this page for the first install, the first scan, review actions, and the policies that decide when runtime calls are allowed or blocked.

Commands Troubleshooting

Quick install

Install the plugin or CLI

Claude Code users should install the plugin from the marketplace. Codex users install the local CLI shim, then add the personal plugin entry.

/plugin marketplace add mannanj/gandalf /plugin install gandalf@gandalf /reload-plugins codex plugin add gandalf@personal

First scan

Build the first local verdict

Run a local scan once after installation. Gandalf scans configured skills and MCP servers, records the result in the local cache, and lets the hook read that verdict quickly at runtime.

gandalf --target all --engines local gandalf --target all

Claude Code

Use the plugin skill

In Claude Code, run /gandalf:gandalf or ask Claude to use Gandalf. The hook checks cached verdicts on skill and MCP calls before the tool runs.

If the CLI is not on PATH, the hook prints the setup command that installs the stable local shim.

Codex

Use the Codex plugin

Start a new Codex session after installation, then pick Gandalf from /skills, type $gandalf, or ask Codex to use Gandalf to review cached findings.

Non-interactive runs can still use the CLI directly for summaries, review, and scan commands.

Reference

Command reference

Command What it does
gandalf --target all Scan skills and MCP servers.
gandalf --target all --engines local Scan everything with the offline local engine.
gandalf --agent-summary Print the cached high-risk launch summary.
gandalf --review Review active findings and choose next actions.
gandalf --activity Show scan, override, and hook activity.
gandalf --install-agent-adapters . Write repo adapters for the supported agent harnesses.

MCP checks

MCP checks and enforcement modes

Gandalf discovers configured MCP servers, materializes a redacted scan surface, and checks launch commands, endpoint metadata, env/header names, and optional model-facing tool descriptions.

Default: warn

MCP policy defaults to warn. It nudges on unscanned servers and logs calls without blocking them.

Enforce when ready

Use gandalf --set-mcp-policy enforce to block unscanned MCP servers and critical or high-risk verdicts.

Static MCP scans never launch servers. Live introspection is opt-in because it connects to or launches the server to read tool descriptions:

gandalf --target mcps --mcp-introspect --engines local,skillaudit

Review flow

Review, acknowledge, and mark false positives

Use gandalf --review to walk active findings from an agent session. Choose mark-fp only after reviewing benign documentation-like matches. Choose ack when you saw the risk and explicitly want runtime to allow it.

False-positive marks live in the local triage file and persist across rescans unless a new finding appears.

Cache

Cache and rescan behavior

Verdicts and history are stored under the local Gandalf cache. Missing, corrupted, unreadable, or stale cache entries fail closed for skill calls.

When a scanned skill or MCP config changes, scan it again so the runtime hook can compare against a fresh verdict.

Engines

Local versus optional cloud engines

The local engine is offline and dependency-free. Optional cloud or third-party engines add coverage when enabled, but they may send scan content to those services.

Use --engines local when nothing should leave the machine.

Troubleshooting

Common failures

  • No cached scan: run gandalf --target all --engines local.
  • Changed since scan: rescan the changed skill or MCP config before retrying.
  • Expected MCP blocking: check SKILLGUARD_MCP_POLICY or run gandalf --set-mcp-policy enforce.
  • Review noise: inspect the file, then use mark-fp only for a real false positive.

Security

Security and privacy notes

Gandalf reads skill files and MCP configuration. Static scans do not execute skill code or launch MCP servers. Secret values are read in memory for detection and are not written to scan surfaces, findings, cache, or history.

Report bypasses, cache poisoning, secret persistence, or scanner execution bugs privately through the GitHub security advisory flow.
