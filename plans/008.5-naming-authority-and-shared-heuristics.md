## Why this matters

The refactor (001–008) is faithful, but two of the known next product moves have no
architectural seam yet, so each would otherwise mean tearing into freshly-refactored
code:

1. **The Portcullis rename has no naming authority.** `~/.claude/skillguard-cache`
   is declared independently in `config.py`, `store.py`, and `hook.py`;
   `"skillguard.db"` in three places; the `SKILLGUARD_` env prefix scattered across
   `config.py` and `engines/skillaudit.py`. There is no `APP_NAME` constant. The
   rename (`task-brand-names.md`, "do before PyPI") is today a find-and-replace
   across 6+ files.
2. **The Cisco false-positive fix can't reuse the doc-table heuristic.** The
   suppression rule (`"|" >= 3`) is an anonymous inline inside `LocalEngine`. The
   documented fix (`task-cisco-false-positives.md`) is an adapter-side post-filter
   that *reuses* it — impossible while it is trapped in one engine.

## Steps

### Step 1: Naming authority

Add `skillguard/branding.py` (no internal imports) with `APP_NAME`,
`CACHE_DIR_NAME`, `DB_NAME`, `ENV_PREFIX`, all derived from `APP_NAME`. Route
`config.default_cache_dir`, `store.default_db_path`, `paths.db_path`, and the
`config`/`skillaudit` env reads through it. Add `branding.py` to `install.sh`
`MODULES` (the `test_install_sync` ratchet enforces this).

**hook.py STOP condition**: the hook runs standalone and import-guards the package,
so it MUST keep resolving its cache path when the package is unimportable — do NOT
make it `import branding` before `CACHE_DIR`. Keep an inline mirror, documented,
pinned to `branding` by a drift test.

**Verify**: an AST ratchet test asserts the cache-dir name appears as a string
literal only in `branding.py` and `hook.py`'s mirror.

### Step 2: Hoist the doc-table heuristic

Move the `"|" >= 3` predicate into `patterns.is_markdown_table_row(line)`; call it
from `LocalEngine`. Detection output must stay byte-identical (same predicate, same
input).

**Verify**: existing local-engine suppression tests stay green; add a direct unit
test for the function.

### Step 3: Reconnect the roadmap to the product backlog

Add a "What's next after the refactor" section to `plans/README.md` linking
`task.md` / `task-brand-names.md` / `task-cisco-false-positives.md` and the
`README`/`SECURITY` known-limitations, with the rename-before-PyPI ordering, so
closing 010 hands off cleanly instead of dead-ending.
