## Why this order

The two god-files — `cli.py` (1383 LOC) and `mcp.py` (819 LOC) — are 70% of the
package and the heart of the refactor. But you do **not** refactor a 1383-line
file with no test on its main path. So the sequence is:

1. **Safety net first** (001) — characterization tests that pin current
   behavior, so every later refactor has a tripwire.
2. **Cheap DRY + bug fixes** (002–003) — low-risk consolidations and correctness
   fixes that land on the *simpler* pre-decomposition code.
3. **Quality backstop** (004) — ruff/mypy/CI so the big refactors have a
   mechanical net.
4. **The reusability centerpiece** (005) — a real `Engine` protocol + registry.
5. **The big decompositions** (006 cli, 007 mcp) — split the god-files into
   modules, behind back-compat re-exports so tests don't churn.
6. **Security hardening + investigations** (008–009) and **docs** (010).

## Dependency notes

- **Everything depends on 001.** The cli.py refactors (005, 006) and the
  mcp.py refactor (007) are only safe once the characterization tests exist.
- **002 before 005** — the engine protocol uses the shared severity helpers and
  `_util` added in 002.
- **004 before 006/007** — mypy/ruff catch the mechanical errors a large module
  split introduces; running the big decompositions without them is riskier.
- **005 before 006** — cli.py's decomposition extracts the engines into their own
  modules using the registry introduced in 005.
- **003 is independent of the decompositions** — do it early so the bug fixes
  land on the smaller, current code rather than being rewritten mid-split.
- **010 last** — the agent guide should describe the architecture *after* the
  engine protocol and module split settle, or it documents a moving target.

## Findings considered and rejected

- **Full `commands/` package (one file per subcommand)** — at 3 read-commands
  (history/activity/show) a single `commands.py` is right-sized; a package would
  be premature abstraction. Reconsider only if the CLI surface ~doubles. (Folded
  into 006 as a single module, not a package.)
- **Standalone unit tests for `model.py`** — already fully exercised via
  `test_triage.py`/`test_cache.py`; the dataclasses are trivial. Low leverage.
- **`pip-audit` in CI** — with zero runtime dependencies its value is near-nil
  (it would only audit optional extras when installed). Note in 004, don't gate.
- **Unifying `mcp.py`'s redact-vs-flag double walk across the redaction and
  detection paths** — structurally parallel but produces two different outputs
  (redacted strings vs. Findings); unifying risks coupling redaction to
  finding-generation. Addressed conservatively inside 007 (shared classifier),
  not as a standalone change.
